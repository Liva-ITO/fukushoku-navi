# 復職ナビポータル（仮）

**リワークを使わない人にも、復職準備の型を。**

メンタルの不調で休職した本人（スマホ）と、会社の人事・産業保健スタッフ・上司（PC）をつなぐ Web アプリの試作です。
Built with Claude: Japan 2026 の出品作です。

- デモ（通し）：https://liva-ito.github.io/fukushoku-navi/
  人事が休職者を登録するところから、本人が復職するまでを一本で体験できます
- デモ（画面を見る）：https://liva-ito.github.io/fukushoku-navi/?mode=browse
  登録が済んだ状態から始まり、上のバーで段階を変えて、好きな画面を見られます

画面の人物・会社・記録は、すべて架空です。

## なぜ作ったか

- 過去1年に、メンタルの不調で1か月以上休んだ人か、辞めた人がいた事業所は 12.8%。従業員1,000人以上の事業所では 91.6% です（厚生労働省「令和6年 労働安全衛生調査（実態調査）」）
- 復職しても、5年以内に約半数（47.1%）が再び休職したという研究があります（国内のIT企業1社・うつ病の人の追跡。Endo et al., *Industrial Health* 2013）

作り手の株式会社リヴァは、2011年からリワーク（復職支援のプログラム）を続けてきました。
リワークでは、生活のリズムを整え、少しずつ負荷を上げ、休職をふり返り、会社とのやり取りを練習します。
でも、近くにリワークがない、通う時間がとれない、合わないなどの理由で、使わずに復職する人もいます。そのとき本人は、何をどこまで整えればいいか分からず、会社も、連絡の頻度や言葉に迷います。

このアプリが目指すのは、リワークを使わなくても、復職までの準備が仕組みとして進むことです。
「リワークを使うかどうか」ではなく、「リワークで整えるか、自分で整えるか」を選べるようにします。

## 何ができるか

### 本人の画面（スマホ）

段階に合わせて、ホームが切り替わります。

- **急性期**：休むことがいちばんの仕事。やることを求めません。会社への返信は、例文を選ぶだけ
- **回復期**：日記で生活を残し、「きょうのひとつ」で、生活のリズム・外に出る・仕事に近いこと・休職のふり返りを、1日に1つずつ進めます。しんどい日の分も出ます。やってみた感じで次のステップをすすめ、きつかったら黙って下げます
- **準備期**：自分の取説（調子を崩す前のサインと対処）を作る → 会社に出すレポートを見直す → 産業医との面談を申し込む → 会社から届いた候補日から選ぶ
- **復職後（見守りモード）**：会社からは見えません。自分の取説と、相談の入口だけが残ります
- **今日はしんどい**：押すと画面が静かになります。段階は変わらず、会社にも伝わりません
- 段階が進んだときは、一度だけお祝いの画面が出ます（復職は「ゴールじゃなくて、スタート」）

### 会社の画面（PC）

- 休職者の一覧と「対応が必要なこと」。開けば、今日やることが分かります
- これまでの経緯（段階の切り替え・やり取り・提出物・申し込み）
- 本人への連絡（例文つき、「返信は不要です」の印）、面談の候補日を3つまで送る
- 復職までの手順（産業医との面談 → 会社の判断 → 主治医の診断書 → 復職日と配慮）
- 上司を窓口にする会社では、上司は自分が担当する人の、段階・やり取り・面談の日程だけを見られます

### 大事にしていること

- **会社の画面には、本人が提出したものと、やり取りだけを出します。** 日記の中身、気分、休息モードは会社に見せません
- **判断するのは人です。** 段階を進めるのも、復職を決めるのも、会社・産業医・主治医です。アプリもAIも、病状や回復の見立てはしません
- **元の職場に戻ることを前提にしません。**

## Claude の使い方

### アプリの中で（Claude API）

AIを呼ぶのは、会社の画面の2か所だけです。本人の画面からは呼びません。

1. **経緯の要約**：担当が替わったときや面談の前に、「いまどこにいて、会社は何をすればいいか」を30秒でつかむためのもの。段階ごとの期間はコードで計算し、AIには2〜3文の要約と、会社がいますること（3つまで）だけを頼みます。「順調」「心配」のような見立ての言葉は使わせません
2. **連絡を送る前のヒント**：「返信がない」「体調をうかがう」などの場面を選ぶと、伝え方のヒントを2〜3個と、言い換えの例を1文だけ返します。代わりに書くことはしません。急かす言い方や、返信の催促はすすめないようにしています

- AIに送るのは、その画面ですでに見られる経緯か、書きかけの文だけです。名前・部署・日記・気分は送りません
- 鍵（APIキー）はブラウザに置かず、中継サーバー（Cloudflare Workers）から呼びます（`worker/`）
- 詳しくは [docs/ai-summary.md](docs/ai-summary.md)

### 作るときに（Claude Code）

作り手はエンジニアではありません。決めるのは人、手を動かすのは Claude Code、という分担で作りました。

- **CLAUDE.md**：守ること（会社に見せないもの、AIに判断させないこと、言葉づかい）を書いておき、毎回そこから外れないようにしました
- **フック**：公開リポジトリなので、APIキーや社外秘の言葉が入るのを、コミットの前に止めます（`.claude/settings.json`、`scripts/check-public-safety.mjs`）
- **サブエージェント**：急性期の本人・忙しい人事・産業医・UI/UXの専門家の目で、画面を見直します（`.claude/agents/`）
- **スキル**：「押しつけない」「責めない」「後退と言わない」など、リワークの現場で大事にしてきた言葉の原則で、画面の言葉を確かめます（`.claude/skills/wording-check/`）
- 作った順番と、決めたことの記録：[docs/claude-log.md](docs/claude-log.md)

## 動かし方

```bash
npm install
npm run dev
```

http://localhost:5173/ で開きます。AIの機能を手元で試すときは、`worker/` を `npx wrangler dev` で動かし、`.env.local` に `VITE_SUMMARY_URL` を入れます（鍵は `worker/.dev.vars` に置き、リポジトリには入れません）。

## 技術

React + TypeScript + Vite（GitHub Pages）。保存はブラウザの中だけです（サーバーやデータベースは持ちません）。AIは Claude API を Cloudflare Workers から呼びます。
