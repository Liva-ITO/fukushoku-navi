# Claude とどう作ったか

ひとりで出場している。作り手は株式会社リヴァの代表（エンジニアではない）と、Claude Code。
決めるのは人、手を動かすのは Claude、という分担で進めている。

## 11/2（月）

**キックオフのあと、ゼロから開始**

- Vite + React + TypeScript の土台を、手で一つずつ書いて作った（テンプレートの生成物を使わず、必要なファイルだけにした）
- デモ操作バー（本人／人事の切り替え、段階、休息モード、最初に戻す）と、急性期の本人ホームを作った
- 画面の言葉は `src/constants/labels.ts` に集め、言葉だけを直せば画面が変わる形にした。言葉を決めるのが、エンジニアではない代表の仕事になるため

**ひとりで品質を守るための仕組みを、最初に入れた**

- **公開前チェックのフック**：公開リポジトリなので、取引先の名前や金額、APIキーがうっかり入るのがいちばん怖い。Claude Code の PreToolUse フックと git フックの両方から同じチェックを呼び、コミットの前に止める。社外秘の言葉の一覧はリポジトリの外に置き、一覧そのものが公開されないようにした
- **言葉づかいチェックのスキル**：「押しつけない」「責めない」「後退と言わない」など、リワークの現場で大事にしてきた言葉の原則を、Claude が毎回同じ基準で確かめられるようにした
- **当事者の目で見るサブエージェント**：急性期の本人、忙しい人事、産業医。立場で気になるところがまったく違うので、3つに分けた。いずれも架空の人物で、実在の人のデータは使わない

**公開前チェックを試した**

- 金額と社外秘の言葉を入れたテスト用ファイルでコミットを試し、Claude Code のフックと git フックの両方で止まることを確かめた

**急性期の本人の目で、最初の画面を見直した**

- サブエージェントから6つの指摘が出た（例：開いて最初に「人事からの連絡」が目に入ると、それだけで胸が詰まる／「休むことがいちばんの仕事」の「仕事」という言葉で、会社に迷惑をかけている自分を思い出す）
- どれを直すかは代表が決める → 5つを直し、1つはプロジェクトメンバーに聞いてから決める
  - 人事からの連絡は1行にたたみ、本人が開いたときだけ本文が見えるようにした
  - 「仕事」にたとえない言い方に変えた
  - リヴァ面談はいきなり申し込みにせず、誰から連絡が来るかを見せてから申し込む形にした
  - 次の時期に進む目安から「意欲」を外し、リワークの利用の目安でもある「週2日は外出できる」にそろえた（代表の判断）
  - 記録への入口を「日記」にした

**回復期・休息モード・日記を作った**

- 回復期のホーム：今日のすること、「今日はしんどい」、準備の進め方（リヴァトレ／リヴァBiz／自分のペース）、次の段階までにやること、準備期への入口（会社と面談／心理の専門家に相談）
- 急性期で決めた「いきなり申し込みにしない」を、回復期の面談の申し込みにも同じ部品で使った
- 休息モード：提案を引っ込め、色を落として静かにする。段階の表示はそのまま
- 日記：タップ中心で1分以内に終わる形。気分は言葉を出さず顔だけで選ぶ。書けなかった日は空欄のままにし、×や警告色を使わない。ブラウザの音声入力にも対応

**人事との連絡タブを作った**

- 急性期は例文を選ぶだけで返せる。回復期からは自分の言葉で書き、例文は「書き出しの例」として下に置く
- 通院のあとの報告は、状態を選ぶだけで人事に届く
- 「会社に届いたもの」で、本人が送ったものをいつでも確かめられる

**回復期の画面を、本人と産業医の目で見直した**

- 本人役からは「次の段階までにやること」がノルマに見える、しんどい日に空のチェック欄が目に入るとつらい、など
- 産業医役からは、休息モードから緊急時の案内にたどり着けない、具体的な条件が段階を切り替える基準のように読める、など
- どれを直すかは代表が決める

**指摘を一つずつ検討する中で、代表から「そもそも段階の全体像がない」と気づきが出た**

- サブエージェントの指摘は個々の言葉づかいだったが、代表は「本人が自分の現在地と、この先の見通しを持てない」ことが根っこだと見た
- リヴァが企業向けに使ってきた「不調から安定勤務までの流れ」の図をもとに、本人向けの「復職までの流れ」を作った。調子の線は一直線ではなく波を描きながら上がる形にし、「いまここ」を示す。どの段階からでも開ける

**指摘の続きを、代表が一つずつ判断した**

- 「次の段階までにやること」は「次の段階の目安」にし、やることではなく「できている状態」で書いた。次に進むかを決めるのは面談だと添えた
- 「しんどい日の配慮をもっと前に」という指摘は、代表の判断で採らなかった（気を使いすぎると、かえって不自然になる）。「今日はしんどい」は目立つボタンから小さな文字リンクにした
- 代表から「面談の申し込みが画面の下に急に出てくる」と指摘。面談を「次の段階の目安」の続きに入れ、目安に近づいたら申し込める流れにした
- 代表から「今日のすることは、チェックしてどうなるのか」と問われた。実際、印がつくだけでどこにもつながっていなかった。毎日の記録は日記、目指すことは目安が担っているので、枠ごとなくした
- 代表から「回復期の目安の中身は、急性期から回復期に進むときのものになっている」と指摘。「準備期に進む目安」として、厚生労働省の職場復帰支援の手引きにある判断基準の例を参考に仮置きした。基準そのものはリヴァで詰める
- 面談の入口を、代表がリヴァの実際の運用に合わせて組み直した
  - 急性期から回復期へは、リヴァの心理の専門家との面談で確かめる（必須）。目安の見出しは「次の段階への目安（焦らなくて大丈夫）」にし、気づかいの言葉を重ねすぎないようにした
  - 回復期から準備期へは、リワークならプログラムの中で確かめるので、アプリからは申し込まない。自分のペースで準備する人だけ、会社との面談を申し込む
  - リヴァとの面談は、段階を進めるためではなく、相談したいときに選ぶもの。「相談」タブに、復職コーディネーターとの面談のリクエストを置いた
  - 面談の回数（チケット）は人事側で管理するので、本人の画面には出さない。申し込みではなく「リクエスト」にしたのは、回数が残っていなくても本人のニーズが人事に見えるようにするため
- 自分のペースで準備する人がひとりで抱え込まないよう、代表の案で「おすすめの本」とリヴァへの相談の入口を置いた。本の書名は、国立国会図書館の書誌情報で確かめた
- 面談の回数（チケット）が残っていれば「申し込む」、なければ「リクエスト」にした。代表の最初の案は「チケットが補充されるまでお待ちください」だったが、代表自身が「いつまで待てばいいんだよと思うかも」と気づき、Claude と相談して「面談の日程か、難しい場合はそのことを、7日以内にお知らせします」と、必ず返事が来る形にした。日数は代表が決めた
- 産業医役から「休息モードからつらいときの連絡先にたどり着けない」と指摘。代表の判断で、「今とてもつらいとき」という特別な入口は作らず、休息モードにリヴァへの相談を置いた。面談の回数が残っていないときは、リクエストの代わりに主治医と公的な相談窓口を出す。窓口の電話番号は厚生労働省のページで確かめた
- 代表から「急性期は体調を大きく崩している時期なので、急性期にも同じものを」と追加。急性期のホームにも同じ相談の枠を置いた
- 代表から「本人の画面で、運営会社の名前を言わなくてよい。極力その色は消して」。本人にとって大事なのは「誰に相談できるか」で、どこの会社かではない。画面から社名とサービス名を外し、「復職コーディネーター」「心理の専門家」「通うリワーク／オンラインのリワーク」にした。CLAUDE.md の決まりにも加えた
- 本人役・人事役から「面談を申し込んだことが会社に伝わるのか分からず、押すのをためらう」と指摘。代表の判断は「申し込んだことは会社が把握する。話す内容は会社は知らない」。申し込みとリクエストの確認の文に、そのとおり書き足した
- 言葉づかいチェックで「『押してください』は指示の形」と指摘。Claude の案「押すと、画面が静かになります」に対し、代表から「画面が静かになる、は意味が分からない人がいる」。本人の気持ちに寄せて「画面を見るのもつらい日もありますよね。そんな日は『今日はしんどい』を押すと、休むための表示だけになります」にした

**役割を分けた：本人側はスタッフ、人事側は代表**

- 準備期の本人画面はスタッフに任せ、代表は人事画面に集中することにした

**人事画面を作った**

- 一覧：通知の見本、休職中の人数・対応が必要な件数・面談チケットの残り（会社全体、補充ボタンつき）、「対応が必要なこと」、休職者の一覧
- 詳しい画面：これまでの経緯（段階の切り替え・やり取り・提出物・申し込みを日付順に1本で）、段階を変える、本人に連絡する（例文・「返信は不要です」）
- 段階を切り替えるのは人事（代表の判断）。社員Aは本人画面とつながっていて、人事が段階を変えると本人の画面が変わる。本人が休息モードにしても、人事の画面は何も変わらない
- 会社に出さないもの（日記の中身・気分・休息モードかどうか・面談で話した内容）は、データの形の時点で人事画面に渡さない作りにした
- 人事役のサブエージェントから6つの指摘（段階が選んだ瞬間に変わる、対応済みにできない、送り先を取り違えそう、など）。一つずつ代表が判断している
- 段階：Claude は「プルダウン＋確認」を提案したが、代表の想定は「段階ごとに見る画面が変わる」だった。プルダウンをやめ、段階ごとに人事がすることを一言出し、［回復期に進める］［準備期に進める］で進める形にした。急性期は、心理の専門家との面談が済むまで押せない。戻すことは「ありうるが、あまり起きない」ので、小さく［前の段階に戻す］を置き、確認で「戻す前に、本人と面談して理由を説明してください」と出す
- 「対応が必要なこと」に［対応済みにする］を付けた。押すと一覧から消え、その人の経緯に「対応済み」と残る。各項目に受け付けた日を出し、満了日のように期限があるものは「期限まであと○日」も出す。並びは期限が近いもの → 新しく届いたもの。新着は、詳しい画面を開いたら消える
- 代表がスマホで人事画面を開き「読みにくい」→ 幅が狭いときは項目を縦に積み、表は横にスクロールにした
- 代表から「新着を押しても、何が新着か分からない」。新着を「本人から届いた連絡・提出物・申し込みのうち、まだ開いて見ていないもの」と決めて一覧の下に書き、詳しい画面の経緯では、その項目に「新着」の印と色をつけた

## 11/3（火・祝）

**人事役の指摘の続き**

- 「本人に連絡する」に宛先の名前がなく、［送る］で即送信だった。人事役の「社員Dに送るつもりが社員Aに、が一番怖い」を受け、見出しを「社員Aさんに連絡する」にし、送る前に宛先と本文をもう一度見せて確かめる一段を入れた（代表が承認）
- 人事役から「段階を見ないまま、どの例文も選べる。急性期の人に日程を聞く例文を送れてしまう」と指摘。Claude は「急性期は返信を求めない」と提案したが、代表から「急性期の連絡って実際どんなものがある？」と問われ、調べ直した
  - 職場復帰支援の手引き（厚生労働省）では、制度の説明は休業の始めにパンフレットなどで渡す。ただし協会けんぽの傷病手当金は、期間が終わってから申請し、そのたびに会社の証明と主治医の意見がいる。急性期でも手続きのやり取りは必ずある
  - 手引きには「診断書や傷病手当金申請書の提出のタイミングに（連絡を）行うと、本人への負担が軽減されることがある」とある
  - これを受け、急性期の例文は「体調を気づかう一言／傷病手当金の申請書／診断書」、回復期からは面談の日程を足した。返信がいるかどうかは本文に書かず「返信は不要です」の印だけで伝え、例文を選ぶと印も合わせて付く（または外れる）形にした
- 代表から「詳しい画面の一番下にも『一覧に戻る』がほしい。いちいち上まで戻るのが面倒」。下にも置いた
- 人事役から「経緯で、返信不要をつけたか、面談が日程調整中か実施済みかが追えない」と指摘
  - 人事から送った連絡に「返信は不要」の印を出した
  - 面談は1件を1行にまとめ、状態の印が「申し込み → 日程決定 → 実施済み」と変わる形にした。右側に「面談」の枠を置き、会社との面談は人事が日にちを入れて日程を決め、実施を記録する。決まった日にちは本人の画面にも出る
  - Claude は「申し込み → 実施済み」だけの簡単な形も示したが、代表の判断は「日程決定はあったほうがいい。人事はひとりひとり覚えていられないし、産業医やほかの担当者との共有の意味でも」
  - 復職コーディネーターとの面談は、実施したことを会社に伝える（代表の判断）。話した内容は伝えない。デモでは支援機関からの報告を見本のボタンで再現した
- 人事役から「［5枚補充する］が確認なしで押せる。リクエストが来たとき人事が何をすればいいか書いていない」と指摘。Claude は手順の一文を足す案を出したが、代表から「対応が必要なことのところがよく分からない。リクエストは受理されたら本人に連絡が行き、支援機関と日程調整になるだけ。人事側で何をするの？」
  - 整理し直すと、コーディネーターとの面談の申し込みに人事がすることはない。なのに「対応が必要なこと」に出していた。外して、「面談」の枠と経緯で見るだけにした
  - リクエストに人事ができるのは「チケットを補充するかどうか」だけ。項目にそう書き、［チケットを補充する］を隣に置いた。補充すると、待っているリクエストは自動で受け付けられる（代表の判断）
  - 補充は、押したら確認を挟む
  - 架空の社員Cの「対応が必要なこと」は、調べた急性期の実務に合わせて「傷病手当金の申請書が届いた」にした

**復職の確定を作った**

- 職場復帰支援の手引き（第2〜第4ステップ）をもとに、Claude が「主治医の診断書 → 産業医との面談 → 復職日と配慮 → 確定」の案を出した
- 代表から「産業医と面談したあとに、主治医に診断書をもらってきてもらう流れにしたい。厚労省の流れには、リワークという考えが抜けている」。一方で「診断書のあとに産業医面談としている会社は、運用が乗らなくなる。どう思う？」
- Claude は、手引き13ページにも「あらかじめ主治医に職場で必要とされる業務遂行能力の内容等を伝えた上で、意見書を書いてもらうことが望ましい」とあり、代表の順番は手引きの勧める形でもあると伝えた。そのうえで、順番は会社の設定で選べるようにし、最初は代表の順番にした
- 代表の気づき「順番を決めないと押せない、としなければよいのか」。手順はどこからでも記録でき、［復職を確定する］だけが3つそろうまで押せない形にした。順番の設定は、並びと案内を変えるだけになる
- 就業上の配慮は書けるが、必須にはしない。産業医がいない会社は「会社が決めた担当者との面談」とした（手引きにも、50人未満の事業場の進め方がある）
- 確定すると段階が「復職（見守りモード）」に変わり、本人の画面に復職日が出る。本人の準備期の画面はスタッフが作るので、Claude が足したのは復職日の一文だけ
- 代表がスマホで試して2つ指摘
  - 「診断書を受け取った、を押しまちがえても戻せない。面談の日程や復職日も、一度決めると直せない」→ 受け取りと実施済みは取り消せるように、面談の日程は［日程を変える］で決め直せるようにした（会社との面談も同じ）。復職日の［変える］は目立つボタンにし、書き直している間は確定できないようにした
  - 「手順の順番は一度決めればよく、人ごとに決める話ではない。最初に会社として設定し、あとはそれが使われるのがいい」→ 順番の設定を一覧の下の「会社の設定」に移した。ひとりひとりの画面には、いまの設定を一言出すだけにした
- 急性期の［面談が済んだことを記録する］について、代表から「なんだっけそれ」。説明しながら Claude が気づいた：面談をするのは支援機関の心理の専門家で、済んだことを知っているのも支援機関。人事が押すボタンはおかしく、コーディネーターとの面談（実施の事実だけ支援機関から届く）ともそろっていない。代表の了承で、支援機関から実施の報告が届く形にそろえた（デモは見本のボタン）

**もとの仕様と照らし合わせ直した**

- データ分析画面の案を、Claude がもとの仕様を確かめずに一から作っていた。代表から「もともとの仕様にあった分析とは違ってないか？」→ 確かめると、核の「リワーク利用の有無による復職率・再休職率の違い」が抜けていた
- 代表から「もっかい全部見直して」。仕様書（01〜10）といまの作りを照らし合わせ、仕様とずれているもの（会社の復職判断の段がない、復職を確定しても会社から見えたまま、つらいときの連絡先がいつでもたどれる場所にない、分析の中身）と、代表の判断で変えたもの、まだ作っていないものに分けて一覧にした。以後、案を出す前に仕様を確かめる
- 会社の復職判断：代表「会社が最終的に復職判断する、これはとても大事なこと」。手順を4つ（産業医との面談 → 会社の復職判断 → 主治医の診断書 → 復職日と配慮）にした。判断は産業医との面談のあとにしか押せない。「もう少し準備が必要」と判断したときは、段階を戻さず準備期のまま産業医との面談をやり直す形にした（代表の判断。段階を戻すと本人には後退と映る）

- 満了日が近いことを、画面が自動で知らせていなかった（デモの社員Bに手で書いてあっただけ。2人とも指摘）。代表「満期が近いのに気づかないのはまずい」。満了日の60日前から、全員について「対応が必要なこと」に自動で出し（延長が要るか、主治医・産業医の意見を早めに確かめる、と添える）、一覧の満了日には「あと○日」を付けた。60日は本来は会社の設定で決めるもの（いまは見本として固定）
- 回復期→準備期のボタンが条件なしで押せる（2人とも指摘）。Claude は「プログラムから進めてよいと報告が届く」案を出したが、代表は「リワーク施設側で判断することはしない。会社設定で会社側が条件を選び、満たせたらボタンが出る形に」。リワークでは施設から会社に月次レポート（出席日数・出席率など）が届くので、それを条件に使えるようにした。会社の設定に「準備期に進める条件」を置き（リワークの出席率○%以上／本人が目安をそろえている／会社との面談が済んでいる）、人事の画面の回復期に、その人に当てはまる条件を「済み／まだ」で出す。代表が見せてくれた社内のステップの資料の数字は、公開リポジトリに入れないため使わず、条件は一般的な言い方と見本の値にした

- 11/3 データ分析（B3）：比較の見せ方は変えない（人事・産業医は、選んだ人の状態が違うことを分かったうえで見るため）。割合の横に人数を出す（例：90%（9/10人））。母数が見えると、上司や経営への説明に使いやすい

- 11/3 急性期→回復期（C1）：心理の専門家が結論を返す形は取らない（支援機関が段階を判断する形になり、面談の中身を会社に出さない決まりともぶつかるため）。面談のあと、本人が「回復期に進みたい／もう少し休みたい」を選んで会社に送る。会社に届くのは本人が送ったものだけで、判断は会社のまま

- 11/3 急性期の面談（伊藤さんの画面確認から）：心理の専門家の面談とコーディネーターへの相談を同時に申し込めて、同じ日程の候補が2組並んでいた。どちらも仕様上は急性期にあってよい面談なので、消さずに「1つずつ」にした。申し込み中は、もう片方に理由を一文で出す。日程の候補も分けた

- 11/3 急性期の「次の段階へ」：「目安」だと開かれないので見出しを「次の段階へ」に。何をすれば回復期に進めるかを、3つのチェック → 心理の専門家と面談 → 会社に希望を伝えて回復期へ、の道すじで見せ、いまの位置に「いまここ」を付けた（ナビなので）

- 11/3 面談の重なり（伊藤さんの画面確認から）：前の版のデータが残っていると、2つの面談を同時に申し込めた状態が見えていた。画面のボタンを消すだけでなく、状態を変える処理でも止めるようにし、保存の版を上げて古いデータを読み込まないようにした。「どれも難しい」は文字だけで「やめる」に見えていたので、日程の候補と同じ枠にそろえ、見せ方の決まりに6番目として足した

- 11/3 急性期の面談の担当（伊藤さんの指摘）：回復期に進む前の面談（チケットなし・リワークの相談も）は復職コーディネーター。しんどいときの相談（チケット）は、急性期と休息モードでは心理の専門家、それ以外の時期は復職コーディネーターのまま。申し込んだときの相手を覚えておき、お知らせや人事の画面の名前もそれに合わせる
- 11/3 面談のあとのナビ：本人が人事に実施を連絡する必要はない（支援機関から会社に実施の報告が届く）。ただ本人から次が見えなかったので、日程が決まったら「次の段階へ」に面談の日を出し、面談が済んだらコーディネーターから「次は、これからの希望を会社に伝えましょう」のお知らせが届くようにした。デモでは本人の画面だけで進められるよう、デモ操作に［面談が済む］を置いた

- 11/3 相談と連絡の分け方（伊藤さんの指摘）：「相談」に連絡が届くのは分かりにくい。相談タブは申し込むところまでにし、支援機関からのお知らせと日程の候補は連絡タブへ移した（「会社には見えません」と添えて人事とのやり取りと分ける）。面談が済んだお知らせのすぐ下から希望を会社に送れるので、会社に送るものは連絡タブにそろう

- 11/3 記録のまとめ（C2）：代表「ひとりでやった場合、特に状況が分からない。会社にちゃんと提出する必要がある」。自分で準備する人は、生活記録表にならったレポート（1日の活動時間・睡眠時間・体調の変化・休職に至った理由・その対策）を会社に出し、会社はそれで判断する。リワークの人は月次レポートで判断する。使うのは両方の判断（準備期に進めるか・復職の判断）。回復期の本人画面に、レポートを作って送る形を作った（睡眠と外出は日記から自動、残りは本人が書く）。準備期の本人画面はスタッフの担当なので、人事の画面の受け皿（産業医との面談の「面談の材料」）と、デモで届いたことにするボタンだけを置いた

- 11/3 レポートの活動時間：代表「その場で選ぶのではなく、日記から自動取得して平均かグラフで」。日記に「日中、横にならずに過ごした時間」（2・4・6・8・10時間以上から選ぶ）を足し、レポートでは14日の平均と日ごとの棒グラフで出すようにした。書いていない日は棒を出さない

- 11/3 回復期→準備期の会社との面談：代表「レポートを出していないと面談ボタンが押せないように」。会社の設定でレポートを条件にしているときは、送るまで［会社と面談する］の代わりに「レポートを送ってから申し込めます」と［レポートを作る］を出す
